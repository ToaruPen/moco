# 会話の開始案内と閲覧体験

## 対象

既存のオペレーターコンソールに、状態に合った空表示と会話のスクロール制御を追加する。
ユーザーから UI・UX の実装を自律的に進める許可を得た範囲として、既存の音声契約と
コンパクトな二ペイン構成を維持する。新しい依存、永続化、サーバー API は追加しない。

## 選択

- 静的な説明だけでは、接続後も初回の説明が残り、次の操作が分からない。
- 初回ウィザードは会話の開始までの操作数を増やす。
- 空の会話欄を現在の接続・マイク状態に応じた案内へ変える方式を採用する。

## 表示と操作

- 未接続時は「接続」からマイクを許可する手順を示す。
- 接続中は許可と接続の待機中であることを示し、接続ボタンも「接続中…」にする。
- 接続済みでマイク OFF なら「入力開始」、ON ならそのまま話せることを示す。
- アイドル終了・音声再接続待ちは「入力開始」で再開、接続切断は「再接続」を案内する。
- 会話が一件でもあれば空表示を取り除く。消去後は最新の接続・マイク状態に合った案内に戻す。
- 入力停止が処理や再生を取り消さないことを会話欄の下部に常設する。
- 会話の各発話に、最初のテキスト受信時刻を利用端末の時計で表示する。更新時に時刻を変えない。
- 会話の末尾を見ている間は新着を追従する。末尾から48px以上離れていれば閲覧位置を維持し、
  会話ヘッダーに「最新へ」を表示する。クリックまたは手動で末尾へ戻ると追従を再開する。
- 「最新へ」のキーボード操作後は、非表示になるボタンから会話ログへフォーカスを移す。
- 会話とアクティビティのスクロール領域に名前とフォーカスを付け、キーボードで閲覧可能にする。

## レイアウト

ユーザーの「洗練されたデザインに」という追加指示を受け、音声設定・会話操作・補助操作を
グループ化する。音声設定は短い日本語ラベルをスマートフォンでも表示し、主な操作は
820px以下で44px以上の高さにする。狭いデスクトップでは上部バーを折り返す。
スマートフォンの固定入力ボタンには共通の不透明な背景を設け、本文との重なりを区別する。

既存の配色トークン、13pxの本文、8/12pxの間隔、境界線主体の見た目を継承する。
会話の空表示は左揃えの短い見出しと説明に限定する。装飾や点滅を追加しない。
320pxでもヘッダー操作が折り返され、長い単語が横にはみ出さないようにする。
820px以下でも会話とアクティビティの高さを制限し、それぞれのログをスクロール可能にする。

## 検証

単体テストを失敗から追加し、状態別の案内、消去後の案内、追従停止・再開、発話時刻、
文字列の安全な表示を確認する。実ブラウザでは320/390/430pxと820/1280pxでスクロール、
長文、フォーカス、配色、操作の可視性を確認する。最後に `just check` を実行する。
実際のマイクや外部Codex/Irodoriへの接続は、この表示変更の検証には使用しない。
