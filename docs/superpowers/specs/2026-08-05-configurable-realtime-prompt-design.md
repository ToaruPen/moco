# Realtimeプロンプトファイル設定設計

## 目的

ローカルのUTF-8テキストファイルを編集することで、各Realtime会話でGPTへ送るプロンプトを置き換えられるようにする。プロンプトの編集内容は、mocoを再起動せず次の会話から反映する。

## 設定契約

厳格YAML設定へ任意パスの`codex.prompt_file`を追加する。

- `codex.prompt_file`が`null`または省略時、mocoは`~/.moco/prompt.md`を探す。
- 暗黙の`~/.moco/prompt.md`が存在しない場合、内蔵Realtimeプロンプトを使う。
- 設定パスは`~`を受理し、ユーザーのホームディレクトリを基準に展開する。
- 展開後のパスは絶対パスでなければならない。相対パスは設定検証で拒否する。
- 設定ファイルは内蔵プロンプトへ追記せず、完全に置き換える。

設定例は`prompt_file: null`を維持し、暗黙パスを説明する。`config/`配下のプロンプト雛形には、編集開始点として現在の内蔵プロンプトを収録する。

## 実行時動作

`CodexRealtimeSession.start()`はCodexプロセスの起動やthread作成より前にプロンプトを解決して読み込む。新しい会話ごとにファイルを再読込するため、daemonを再起動せず編集を反映できる。

プロンプト読込は次の規則に従う。

1. 明示設定パスがあればそれを使い、なければ`~/.moco/prompt.md`を使う。
2. 暗黙ファイルが存在しなければ内蔵プロンプトを使う。
3. 明示設定ファイルが存在しなければ拒否する。
4. 読取不能、非UTF-8、空白のみ、64 KiB超のファイルを拒否する。
5. 検証済み内容をログへ出さず、`thread/realtime/start.prompt`として渡す。

失敗はCodex RPC起動前に発生させ、既存の限定された会話開始失敗経路で通知する。エラーメッセージはプロンプト本文を含めず、失敗分類だけを示す。

## スコープ境界

- browser UIへプロンプト編集機能を追加しない。
- turn単位または会話中のプロンプト更新を追加しない。
- プロンプト本文をtelemetryへ出力しない。
- プロンプト合成、persona schema、互換レイヤーを追加しない。
- 選択されるプロンプト以外は、既存Realtime transport、Irodori合成、会話動作を変更しない。

## テスト

テストファーストで次を確認する。

- 暗黙の既定ファイルがない場合の内蔵fallback。
- 存在する`~/.moco/prompt.md`の読込。
- 明示設定した任意の絶対パスの読込。
- `~`の展開と相対パスの拒否。
- 同一processで後続会話を開始したときの再読込。
- 明示設定ファイル欠損の拒否。
- 読取不能、非UTF-8、空白のみ、過大ファイルの拒否。
- 不正なプロンプトファイルがCodex RPC起動を防ぐこと。
- 設定例とプロンプト雛形がrepository artifactとして有効なこと。

RED/GREEN cycleでは対象テストを実行し、最後に`just check`を実行する。
